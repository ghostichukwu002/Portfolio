Full-stack delivery marketplace

ZENVORA

A delivery marketplace for Nigerian cities, covering food, groceries and electronics. Customers order from local stores, stores run their own dashboards, and riders deliver with dispatch managed by administrators. I designed it, built the frontend and the API, and deployed both.

What it does

Ordering for customers

Shoppers browse and search, choose a delivery area, and check out with cash on delivery. Order history shows each order's status and the rider assigned to it.

Store dashboard

Store staff connect with an access code, accept or reject orders, move them through preparing and ready, and manage stock, prices and offers. Sales figures come from real orders.

Rider workspace

Riders apply with a vehicle and the areas they cover. Once an administrator approves them, they go online, pick up orders, and deliver with a proof note and a confirmation that the cash was collected.

Dispatch desk and trust

Administrators see every order that needs a rider, matched to riders who cover that area, and every change is written to an audit log. Customers can send care requests, and approved stores and riders carry a verified badge.

How it's built

Frontend

Static site on Vercel

Plain JavaScript modules with hash routing and no build step. Vercel forwards API calls to the Render service, so the browser talks to one domain.

Backend

Node.js API on Render

Built on Node's own HTTP server and SQLite module, with no npm packages on the server. Passwords are hashed with scrypt, sessions use HTTP-only cookies, writes are checked against their origin, and requests are rate limited.

Quality

Tests in every layer

158 automated tests cover the API, auth, orders, dispatch, verification and proxy handling. Browser suites walk the full flow across customer, store, administrator and rider accounts. Money is stored as whole kobo to avoid rounding errors.

Next steps

Online payments need a provider and their keys, and email needs a sending service before password resets and support replies leave the app. The current data store is a SQLite file on the server, and the free hosting tier erases it on restart, so the data needs a persistent database before real customers use it. Live rider tracking is the next larger piece after that.
